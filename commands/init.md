# /devmux:init

Detect the project type, check tool availability, apply git config fixes, and generate `.config/wt.toml` for worktree lifecycle hooks.

## What to do

### Step 1: Check tools

Run the tool checker:
```bash
bash ${CLAUDE_PLUGIN_ROOT}/scripts/check-tools.sh
```

If required tools are missing, guide the user through installation before proceeding. `zmx` is optional but recommended.

### Step 2: Detect repo type

Check if this is a bare repo or regular clone:

```bash
git rev-parse --is-bare-repository
```

Also check if we're in a linked worktree (`.git` is a file):
```bash
test -f .git && echo "linked worktree" || echo "not a linked worktree"
```

**If regular clone** (not bare, not a linked worktree): Apply worktree-friendly git config fixes and warn the user that bare repos are preferred:
```bash
git config remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"
git config core.logallrefupdates true
git config push.default current
git config worktree.guessRemote true
```

**If bare repo or linked worktree**: Verify config is correct. Read `git config --get remote.origin.fetch` and fix if needed.

### Step 3: Detect project type

```bash
bash ${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.sh
```

Parse the key=value output to understand the project. Key values:
- `PROJECT_TYPE` — node, rust, python, go, ruby, java, unknown
- `PKG_MANAGER` — npm, pnpm, yarn, bun, cargo, etc.
- `INSTALL_CMD` — the install command for dependencies
- `HAS_SCRIPT_DEV` — whether a dev server script exists
- `DEV_SCRIPT` — the actual dev command
- `FRAMEWORK` — sveltekit, nextjs, vite, etc.
- `PORT_FLAG` — the flag for specifying a port (e.g., `--port`, `-p`)

### Step 4: Check for existing .config/wt.toml

```bash
test -f .config/wt.toml && echo "exists" || echo "missing"
```

If it exists, read it and offer to extend it rather than overwrite.

### Step 5: Generate .config/wt.toml

Create `.config/wt.toml` based on the detected project type. Use the Write tool. Example for a Node.js/SvelteKit project:

```toml
# Worktree lifecycle hooks — generated by devmux:init
# Project: sveltekit | Package manager: npm

# Install dependencies when creating a new worktree
post-create = "npm ci"

# Start dev server in background after worktree creation
[post-start]
server = "npm run dev -- --port {{ branch | hash_port }}"

# Validate before merging
[pre-merge]
check = "npm run check"
lint = "npm run lint"
test = "npm run test:unit -- --run"

# Clean up dev server when removing worktree
[post-remove]
kill-server = "lsof -ti:{{ branch | hash_port }} | xargs kill -9 2>/dev/null || true"

# Show dev server URL in wt list
[list]
url = "http://localhost:{{ branch | hash_port }}"
```

Adapt the hooks based on detected project type and available scripts. Only include hooks for commands that actually exist. For example:
- Only add `test` to `pre-merge` if `HAS_SCRIPT_TEST=true`
- Only add `lint` if `HAS_SCRIPT_LINT=true`
- Only add `post-start.server` if `HAS_SCRIPT_DEV=true`
- Use the correct `PORT_FLAG` for the framework

### Step 6: Update .gitignore

Ensure these entries exist in `.gitignore`:
```
.worktrees/
.worktree-task.md
.devmux.log
```

Read the existing `.gitignore` and append only missing entries.

### Step 7: Check shell integration

```bash
wt config shell install 2>&1 || true
```

Report to the user if shell integration needs to be set up.

### Step 8: Report

Summarize what was configured:
- Project type and framework
- Package manager
- Hooks configured in `.config/wt.toml`
- Any warnings (regular clone, missing tools, etc.)
- Next steps: use `/devmux:spawn` to create worker worktrees
